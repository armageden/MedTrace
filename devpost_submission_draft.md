## Project Title
**MedTrace**

## Elevator Pitch
When a medical-device requirement changes in Confluence (e.g., `5.0 -> 5.5 mL/hr`), MedTrace proves the downstream safety impact, automatically revokes stale approvals across Confluence and Jira, blocks unsafe transitions, and lets engineers create linked Jira re-verification tasks without leaving Atlassian.

## Category / Track
* **Primary Category:** Apps for Specialized Industries
* **Bonus Prize:** Best app with Atlassian MCP

## Inspiration
In regulated medical-device software engineering (IEC 62304, ISO 14971, FDA 21 CFR Part 11), editing a single clinical threshold in Confluence invalidates prior sign-offs and requires re-verifying downstream hazards, Jira work items, and verification tests. Yet engineering teams still maintain traceability matrices in static spreadsheets that drift out of date while developers transition Jira issues to **Done**. MedTrace turns Jira, Confluence, Rovo, and hosted/local MCP clients into a live traceability and release-gate system built natively on Atlassian Forge (`nodejs22.x`).

## What it does
1. **Living 5-Stage Traceability Graph & Matrix:** Connects `ISO 14971 Hazard <-> Confluence SRS <-> Jira Work Item <-> Verification Test <-> Electronic Attestation` inside Jira (`jira:projectPage`, `jira:issuePanel`) and Confluence (`confluence:globalPage`, `confluence:contentBylineItem`), clearly distinguishing unsigned records from drifted approvals.
2. **Content-Hashed Spec Sign-Off & Test Evidence:** Engineers attach `https://` CI verification evidence (synced across links sharing that test) and execute a session-bound electronic attestation over the Confluence page's SHA-256 hash across sibling links sharing that requirement baseline.
3. **Transition-Aware Jira Release Gate (`jira:workflowValidator`):** Moving a compliant issue from `Under Review` into `Done` succeeds when spec linkage, passing test evidence, valid electronic sign-off, and software safety class are satisfied—while missing evidence, drifted approvals, unclassified safety issues, or failing tests block release.
4. **Automatic Drift Revocation & Transitive Blast Radius:** Editing a Confluence requirement automatically revokes stale approvals across Confluence and Jira without resurrecting invalidated sign-offs on revert, and maps downstream affected hazards, Jira issues, and tests with deterministic blast-radius analysis.
5. **One-Action Live Proof Bootstrap:** **Create Live Proof Chain** creates real native artifacts for evaluation—one Confluence SRS page plus linked Jira hazard, implementation, and verification-test issues (using the project's resolved `createmeta` issue type)—without fabricating test evidence, approvals, or compliance. Engineers still record evidence and sign explicitly.
6. **Hosted Atlassian MCP (`rovo:mcp`), Rovo Agent & Stdio Bridge:** Exposes `get-hazard-lineage-action`, `verify-iec-compliance-action`, and `create-reverification-task-action` to AI tools over hosted Atlassian MCP / OAuth 2.1 (with user-scoped permissions), alongside an HMAC-authenticated local MCP server (`mcp-server/index.mjs`) for IDEs and CI pipelines.
7. **Tamper-Evident Audit Log & FDA Dossier Export:** Records every sync, bind, live-proof bootstrap, test update, task creation, and sign-off in a hash-chained Forge ledger filtered by the caller's Jira and Confluence permissions, with printable reports, formula-safe CSV export, and JSON dossiers.

## Honest Scope & Boundaries
* **Assistive tooling, not formal QMS certification:** MedTrace enforces configured traceability and SHA-256 checks; it does not verify test execution authenticity, enforce dual-person QA sign-off, or replace a validated QMS or official FDA eSTAR submission.
* **Software tamper-evidence & Forge KVS boundaries:** Hash chaining + `HMAC-SHA256-SEAL-V1` provide software tamper-evidence in Atlassian Cloud (not hardware WORM, HSM, or third-party PKI); Forge `jira:workflowValidator` is complemented by `verify-release-gate` via `mcp-sync-webtrigger` in CI for automated/REST checks, and Confluence triggers keep per-product KVS partitions fresh on read/gate via `reconcileConfluenceSpecs`.
* **Fallback records:** Tracked Jira issues without native Hazard or Verification Test `issuelinks` use app-managed records labeled `App-Managed` in the UI until native Jira links are added. The primary live judge path uses native Jira artifacts created by **Create Live Proof Chain** instead of those fallback records.
* **Live proof bootstrap boundary:** **Create Live Proof Chain** is explicit and non-idempotent, writes real evaluation artifacts, and never deletes partial artifacts automatically after a failed link/write step. It requires the added `write:page:confluence` installation consent and suitable Jira/Confluence permissions; use an evaluation project/space.

### Option A: 30-Second Zero-Setup Demo Walkthrough
1. Open **MedTrace IEC 62304** on any Jira project (`Apps → MedTrace IEC 62304`), click **Explore Demo Suite** (or **Seed Demo Suite** in the header; confirm overwrite via **Confirm Overwrite & Seed Demo** if an initialized `LIVE` suite already exists) to load the **3-hazard** (`HAZ-101`–`HAZ-103`) Smart Infusion Pump safety scenario.
2. Inspect the live drift on `HAZ-101` / `MED-42` (`5.0 mL/hr -> 5.5 mL/hr`), run **Blast Radius**, test **Test Human Gate**, inspect the hash-chained **Audit Log**, and export the printable **Export Dossier**.

### Option B: Live Jira & Confluence End-to-End Drift Walkthrough
1. **Create the real proof chain:** Open **Apps -> MedTrace IEC 62304** from a Jira project in an evaluation tenant and click **Create Live Proof Chain**. MedTrace creates one Confluence SRS page containing `Bolus delivery threshold: 5.0 mL/hr`, three native Jira issues (hazard, implementation work, verification test; using the project's resolved `createmeta` issue type), two Jira issue links, and one Jira remote link to Confluence, then syncs those exact artifacts. It does **not** record evidence, sign approvals, or mark the chain compliant automatically.
2. **Bind the workflow validator:** In **Jira Project Settings -> Workflows**, edit the workflow transition into **Done** (e.g., `In Progress -> Done` or `Under Review -> Done`) and add validator **MedTrace IEC 62304 Safety Gate**.
3. **Establish the compliant baseline:** In the auto-opened MedTrace inspection drawer, record `PASSED` test evidence (`https://...`) and complete **Sign Off Spec (Attestation)** with `"I CERTIFY THIS ELECTRONIC SIGNATURE"`; **Test Human Gate** passes the compliant release simulation and a real transition into **Done** succeeds after the Jira refresh.
4. **Trigger drift & Atlassian MCP:** Edit the Confluence page from `5.0` to `5.5 mL/hr` -> MedTrace automatically revokes the signature across Confluence & Jira, blocks **Done** transitions, and traces impact in **Blast Radius**. Enable **MedTrace MCP Server** (`https://mcp.atlassian.com/forge/5e49c10e-696f-4984-9d00-4a47d0a5dd99`) under Atlassian Admin **Connected apps**, or use **Ask Rovo (`MedTrace Auditor`)** in Jira, to run `verify-iec-compliance-action` + `create-reverification-task-action` and create a linked Jira re-verification task.
   * **Important for MCP judges:** Forge partitions app KVS separately for **Jira** and **Confluence**, and on dual-installed Jira+Confluence sites Confluence's `asUser()` consent can loop `USER_CONSENT_REQUIRED` (`401 atlassian-token-service-key`), leaving Confluence's KVS partition uninitialized while Jira's KVS partition and **Ask Rovo (`MedTrace Auditor`)** in Jira run normally (external `rovo:mcp` calls hitting Confluence's empty partition fail closed with `initialized: false`).
   * **Manual fallback and operator details:** [docs/00-how-to/04-live-judge-proof.md](docs/00-how-to/04-live-judge-proof.md) documents permissions, partial-artifact behavior, manual setup, and the exact proof checklist.
