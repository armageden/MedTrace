# Architecture

MedTrace runs inside the Atlassian Forge `nodejs22.x` runtime without any `permissions.external.fetch.backend` manifest entries. Compliance evaluations, sharded storage mutations, hash-chained audit entries, Jira/Confluence API calls, and Rovo actions execute inside Atlassian Cloud using Forge KVS (`@forge/kvs`) and Jira/Confluence REST APIs, while authenticated MCP/CI webtrigger responses return requested compliance results to their configured callers.

## Files

- [forge-modules.md](./forge-modules.md) — Forge manifest (`manifest.yml`) Jira & Confluence module parity, local icon resources, RBAC (`assertAuthorizedReader` / `assertAuthorizedOperator` / `assertRovoUserReadAccess`), 14 typed `MedTraceResolverMap` resolvers, `ECO-624` workflow validator boundary, `mcp-webtrigger-fn` hardening, Custom UI architecture, and no-external-fetch / MCP data-return boundaries.

## Configuration & Assets

- [manifest.yml](../../manifest.yml) — Forge `nodejs22.x` modules, `main` (`static/frontend/dist`) and `icons` (`static/icons`) resources, `storage:app`, read scopes, and `write:page:confluence` for the explicit live proof page, CSP `styles: ['unsafe-inline']`, and no `permissions.external.fetch.backend` entries.
- [package.json](../../package.json), [tsconfig.json](../../tsconfig.json), [static/frontend/package.json](../../static/frontend/package.json), & [static/frontend/vite.config.ts](../../static/frontend/vite.config.ts) — Backend TypeScript `NodeNext` module resolution with explicit `rootDir` (emitted backend JavaScript remains CommonJS-compatible under the current package type), backend and frontend npm build (`manualChunks` vendor splitting for `vendor-xyflow`, `vendor-react`, `vendor-forge`), typecheck, manifest validation, docs check, and test scripts.
- [static/icons/medtrace-icon.svg](../../static/icons/medtrace-icon.svg) — Bundled SVG module icon referenced as `resource:icons;medtrace-icon.svg` by `jira:issuePanel` and `confluence:contentBylineItem`.

## Backend Modules (`src/`)

- [src/index.ts](../../src/index.ts) — Forge entrypoint wiring (`resolver-fn`, `confluence-trigger-fn`, `jira-trigger-fn`), 14 Custom UI resolvers (`MedTraceResolverMap`), and re-exports from `src/rbac.ts`, `src/webtrigger.ts`, `src/mcp-server.ts`, and `src/workflow-validator.ts`.
- [src/rbac.ts](../../src/rbac.ts) — Resolver RBAC (`assertAuthorizedReader`, `assertAuthorizedOperator`, `assertJiraSiteAdminPermissions`, `assertOperatorAuthorizedForTarget`), `filterLiveSuiteForCaller`, project + Confluence-page scoped `filterAuditEntriesForCaller`, and the shared Confluence `/operations` helpers (`normalizeConfluenceOperations`, `hasConfluenceWriteOperation`, `hasConfluenceEditorPermission`, `hasConfluencePageCreatePermission`) reused by `src/seeder-identity.ts` and `src/live-proof-scenario.ts`.
- [src/webtrigger.ts](../../src/webtrigger.ts) — Authenticated HMAC-SHA256 `mcpWebtriggerHandler`, `verifyHmacSignature`, `claimNonceDetailed`, and replay nonce checks.
- [src/runtime.ts](../../src/runtime.ts) — `isForgeRuntime()` runtime boundary check.
- [src/types.ts](../../src/types.ts) — Browser-safe shared domain contracts, `PART11_ATTESTATION_PHRASE`, and `MedTraceResolverMap`.
- [src/crypto-utils.ts](../../src/crypto-utils.ts) — `sha256Hex`, `canonicalJsonStringify`, `isKvsConflictError`, `isHttpOk`, `safeParseJson`, `sanitizeKvsKeySegment`, `measureJsonBytes`, `validateHttpsUrl`, `JIRA_PROJECT_KEY_RE`, `JIRA_ISSUE_KEY_RE`, `cloneJsonValue`, and `isSignatureTimestampInvalidated`.
- [src/compliance-engine.ts](../../src/compliance-engine.ts) — 5-stage rule evaluator, `HMAC-SHA256-SEAL-V1` (`computePart11Seal` / `verifyPart11Seal` + `MEDTRACE_PART11_PREVIOUS_SECRETS` key rotation via `resolvePart11VerificationSecrets`), `evaluateIssueReleaseGate` (matching `work.key` / `hazard.key` / `test.testKey` / `reverificationTaskKey` via `linkMatchesIssueKey`), `generateComplianceReport`, `computeBlastRadius`, and `computeMultiBlastRadius`.
- [src/seeder.ts](../../src/seeder.ts) — `SeederService` compliance suite orchestration: `vlock` optimistic locking, `issueKeyIndex` / `medtrace:compliance:meta_index:` O(1) lookup (`GetSuiteOptions`), `kvs.transact()` / chunked staging, `incompleteProjectKeys` scoping, demo fixtures, and compliance mutations (with CAS retry on `createReverificationTask` and shared `testKey` synchronization in `recordTestResult`).
- [src/seeder-storage.ts](../../src/seeder-storage.ts) — Sharded `SHARDED_V2` KVS persistence plumbing extracted from `src/seeder.ts`: KVS key constants, `SignedSpecBaseline` record shape, `ShardedSuiteMetaV2`, shard builders (`shardStringArray` / `shardRecordOfStringArrays` / `buildMetaAndShardItems`), strict batch get/set/delete (rejecting undefined KVS values in `batchGetStrict`), `getBaselineKeyCandidates`, and `resolveTraceLinkByHazard`.
- [src/seeder-identity.ts](../../src/seeder-identity.ts) — Part 11 signatory identity resolution extracted from `src/seeder.ts`: `UserIdentityResolver` contract, `forgeUserIdentityResolver` (Jira `/myself` + `/mypermissions` via `checkJiraBrowsePermissionDetailed`, Confluence `/user/current` + space `/operations` parsed by the shared `hasConfluenceEditorPermission` helper), batched `authorizeAndFilterLiveSuiteDetailed`, `setUserIdentityResolver` test override, `getPart11SigningSecret` (`MEDTRACE_PART11_SECRET`), `resolveCreatemetaIssueTypeRef` (shared Jira `createmeta` issue-type resolution used by `src/seeder.ts` and `src/live-proof-scenario.ts`), and `mapJiraStatusToWorkStatus`.
- [src/teamwork-graph.ts](../../src/teamwork-graph.ts) — `TeamworkGraphService` `JIRA_REST` + `JIRA_REMOTELINK_REST` lookup (`callerMode: 'USER' | 'APP'`, `requireConfluenceLinkToEnrich` short-circuiting) and opt-in `fetchSpecOwnersFromTeamworkGraph` (`confluencePageOwners`, disabled by default in runtime because `read:graph:*` scopes are omitted from `manifest.yml`).
- [src/ingestion.ts](../../src/ingestion.ts) — `LiveIngestionService` paginated Jira/Confluence ingestion, `LIVE_SYNC_CONCURRENCY_BATCH_SIZE = 5` enrichment (`LIVE_SYNC_BUDGET_MS = 11_000`), resumable `nextPageToken` KVS cursors (`SYNC_CURSOR_KEY_PREFIX`), unreached/other-project link preservation, M:N linking, and trigger delegation.
- [src/triggers.ts](../../src/triggers.ts) — Product event trigger & reconciliation handlers extracted from `src/ingestion.ts`: `handleConfluencePageUpdatedTrigger` (revert non-resurrection, CAS retry), `reconcileConfluenceSpecsTrigger` (prioritized 5-page batches across all specs with 8s budget, `asApp()` HTTP-403 fallback, fail-closed drift persistence, and `HTTP 404` `notFound` spec invalidation + `CONFLUENCE_PAGE_NOT_FOUND` audit), and `handleJiraIssueUpdatedTrigger` (with `updatedLinks` deduplication by `id`).
- [src/live-proof-scenario.ts](../../src/live-proof-scenario.ts) — Explicit user-initiated live proof bootstrap creating one Confluence SRS page, three native Jira issues (project's resolved `createmeta` issue type via shared `resolveCreatemetaIssueTypeRef`), native issue/remote links, bounded exact-key ingestion, and post-append `auditEntryCount` / `auditHeadHash` in the returned summary, without fabricating test evidence or attestations.
- [src/audit-log.ts](../../src/audit-log.ts) — `AuditLogService` SHA-256 hash-chained audit ledger (`AUDIT_GENESIS_HASH`, monotonic `setHead` avoiding backward writes, `beforeSeq` pagination, bounded `verifyAuditChain` windows with `DEFAULT_VERIFY_MAX_ENTRIES = 500` / `MEDTRACE_AUDIT_VERIFY_MAX_ENTRIES` and `nextFromSeq`).
- [src/workflow-validator.ts](../../src/workflow-validator.ts) — `workflowValidatorHandler` release gate using O(1) `getActiveComplianceSuite({ issueKeyFilter })` lookup (supporting Hazard, Work, Test, and `reverificationTaskKey` keys), explicit non-release transition pass-through, conservative unknown-transition handling, and Atlassian `ECO-624` scope note.
- [src/mcp-server.ts](../../src/mcp-server.ts) — `McpToolService` & `rovoActionHandler` (`assertRovoUserReadAccess`, read-only `GET` analysis actions, and explicit `CREATE` re-verification task action).
- [src/nonce-store.ts](../../src/nonce-store.ts) — SHA-256 hashed KVS TTL replay nonce store (`MAX_TIMESTAMP_AGE_MS`, `MAX_FUTURE_SKEW_MS`, `NONCE_TTL_MS`).
